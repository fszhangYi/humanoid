# 文档二：训练自己的行走策略——环境需求与步骤

> 适用范围：在现有「G1 MuJoCo 部署能走」的基础上，**自己训练**新的运动策略。  
> 当前仓库（`mujoco_humanoid`）只有 **推理**；训练需要另建环境与训练代码。  
> 本机硬件参考（AutoDL）：RTX 5090 D 32GB、大内存、数据盘约 150GB（空闲常偏紧）。

---

## 1. 先分清两件事

| | 当前项目（已有） | 训练自己的策略（要做） |
| --- | --- | --- |
| 目标 | 加载 `motion.pt` 让 G1 走 | 从奖励学习新的 π |
| 仿真 | 单环境 MuJoCo CPU 即可 | 大规模并行 GPU 仿真 |
| 代码 | `scripts/walk_g1.py` | legged_gym / Isaac Lab / MJX 训练脚本 |
| PyTorch | CPU 版也能推理 | **必须 CUDA 版** |
| 产出 | 网页看行走 | 新的 `.pt` / TorchScript，再部署回来 |

**不要**指望在 `walk_g1.py` 里加几行就能完成训练。

---

## 2. 推荐硬件

### 2.1 GPU

| 档位 | 建议 | 说明 |
| --- | --- | --- |
| 你已有 | **RTX 5090 D 32GB** | 算力足够，优先把软件栈跑通 |
| 够用 | RTX 4090 24GB | 常见租用机型 |
| 更宽裕 | 48GB 级专业卡 | 可开更多并行环境 |

人形行走 PPO 通常不靠「更大卡」硬堆，而靠 **并行环境数 × 稳定训练栈**。

### 2.2 硬盘

| 分区 | 建议空闲 |
| --- | --- |
| 系统盘 | ≥ **50GB**（避免 conda/临时文件把根分区写满） |
| 数据盘（环境+代码+log+ckpt） | ≥ **100GB**，更稳妥 **150–200GB** |

大头：仿真依赖、机器人 mesh、checkpoint、视频/日志。  
**本机若数据盘只剩约 20GB，应先清理再装训练环境。**

### 2.3 内存 / CPU

- 内存：≥ 32GB 可用；你机上百 GB 级很富余  
- CPU：多核有利于部分数据管道；仿真主负载仍在 GPU

## 3. 推荐软件环境（针对 5090 等新卡）

旧版 **Isaac Gym Preview + 原版 unitree_rl_gym** 在 **Blackwell（5090）** 上经常装不上或跑不起来。更稳的选择：

### 方案 A（首选）：Isaac Lab + 适配的 G1 loco 任务

- OS：Ubuntu 22.04  
- 独立 conda（装在**数据盘**）  
- **CUDA 版 PyTorch**（与驱动匹配的官方 wheel）  
- [Isaac Lab](https://isaac-sim.github.io/IsaacLab/)（或当前文档写明支持你 GPU 的版本）  
- 训练算法：PPO（Lab 自带或 rsl_rl 等）  
- 机器人：G1 12-DoF 或你需要的 DoF；观测/动作尽量最终能对齐现有部署  

**优点：** 维护活跃，新 GPU 支持更好。  
**成本：** 需把 G1 任务从 unitree_rl_gym 迁到 Lab，或找已迁移的社区仓库。

### 方案 B：MuJoCo MJX + 自建/开源训练循环

- CUDA PyTorch + `mujoco`（含 MJX）  
- 并行环境在 GPU 上跑  
- PPO 可用自写或 CleanRL / skrl 等  

**优点：** 与最终 MuJoCo 部署同引擎，sim2sim 落差更小。  
**成本：** 要自己搭好奖励、域随机、导出策略。

### 方案 C：原版 unitree_rl_gym + Isaac Gym（仅当兼容性确认）

- 严格按宇树 README 的 CUDA / Isaac Gym / PyTorch **旧版本组合**  
- 最好用官方验证过的 Docker/镜像  

**仅当**文档或镜像明确支持你的 GPU 再选；5090 上优先 A/B。

### 明确不建议

- 在现有 `mjviser` 环境里硬装 Isaac（易与查看器依赖冲突）  
- 用 **CPU 版 PyTorch** 做大规模人形训练  
- 系统盘空间不足时强行 `conda create`

## 5. 训练步骤（通用流程）

下面按「做完能部署回本项目」来写。无论选 Lab 还是 MJX，骨架相同。

### 步骤 0：定任务规格（先写清楚再写代码）

与现有部署对齐时，建议尽量保持：

| 项 | 现有部署参考 |
| --- | --- |
| 控制关节 | 12 维腿部 |
| 底层 | PD → 力矩（或训练时等价） |
| 策略频率 | 约 50 Hz（dt=0.002，decimation=10） |
| 观测维 | 47（若要直接替换 `motion.pt`） |
| 动作 | 12 维，残差 × `action_scale` + `default_angles` |
| 命令 | `[vx, vy, yaw_rate]` |

若你改了观测或动作定义，**必须同步改** `walk_g1.py` 与 `g1.yaml`，不能只换权重文件。

### 步骤 1：准备机器人与场景

- 使用与训练一致的 G1 模型（质量、碰撞、关节限位、执行器）  
- 地面摩擦、初始姿态（蹲站默认角）与配置写进 env  
- 记录 mesh/XML 版本，避免训练与部署各用一份不一致模型  

### 步骤 2：实现环境（Env）

最少要实现：

1. **reset**：随机或固定初始状态、命令采样  
2. **step**：应用动作 → 仿真若干子步 → 返回 obs, reward, done, info  
3. **观测**：与部署同一套特征与缩放（若目标是热替换 `motion.pt`）  
4. **终止**：摔倒（根高度/倾角）、超时、非法状态  
5. **（强烈建议）域随机**：质量、摩擦、PD 增益、观测噪声、推力扰动、控制延迟  

### 步骤 3：设计奖励（决定「走成什么样」）

常见项（示例，需调权）：

- 跟踪线速度 / 角速度命令  
- 存活（不倒）  
- 脚触地节奏、步态对称  
- 动作平滑、能耗、力矩惩罚  
- 关节限位、撞击惩罚  
- 高度/姿态保持  

先能「不倒地缓慢前进」，再提高速度与鲁棒性（课程学习）。

### 步骤 4：配置 PPO（或其它算法）

典型超参维度（具体数值跟框架默认走，再扫）：

- 并行环境数：数百～数千（显存允许范围内）  
- 每次更新的 horizon / batch  
- 学习率、clip、GAE λ、γ  
- 网络：MLP；若观测含历史，可加 frame stack 或 LSTM  

### 步骤 5：开训与监控

```text
启动训练 → TensorBoard/W&B 看 reward、episode length、速度跟踪误差
定期存 checkpoint
定期在「单环境 MuJoCo」里评估（更接近本项目部署）
```

关注：

- 是否只学会「原地抖」或「跪地蹭」  
- 速度跟踪是否跟上 `cmd`  
- 域随机加大后是否崩溃（过拟合无随机仿真）  

### 步骤 6：导出策略

目标格式尽量与现有加载方式一致：

```python
torch.jit.load("xxx.pt")
# 输入: (1, num_obs)  输出: (1, num_actions)
```

导出前用 **与部署相同的 obs 拼装** 做一次前向对齐测试。

### 步骤 7：部署回本项目（sim2sim）

1. 将新权重放到例如 `third_party/unitree_rl/my_policy.pt`  
2. 若观测/PD/默认角有变：改 `g1.yaml` 与 `walk_g1.py`  
3. 验证：

```bash
conda activate /root/autodl-tmp/conda-envs/mjviser
cd /root/autodl-tmp/mujoco_humanoid
python scripts/walk_g1.py --no-view --seconds 8 --vx 0.5 \
  --policy third_party/unitree_rl/my_policy.pt
```

4. 再开 `bash scripts/run_walk.sh`（或改脚本指向新策略）在 **6008** 看  

### 步骤 8：（可选）真机

仿真能走 ≠ 真机能走。真机还需：

- Unitree SDK / DDS 通信  
- 更保守的增益与速度  
- 可能的系统辨识与域随机加强  
- 安全：绳索、急停、场地  

真机流程以宇树官方 `deploy_real` 文档为准，本仓库未覆盖。

## 6. 建议的目录规划（训练机）

```text
/root/autodl-tmp/
  conda-envs/g1_train/          # CUDA 训练环境（与 mjviser 分离）
  g1_rl_train/                  # 训练代码仓库

    configs/

    scripts/export_jit.py
    logs/
```

原则：**训练环境与可视化环境分开**，避免依赖互相污染。

## 8. 最小可行路径（MVP）

若目标只是「尽快训出一个能在本仓库 MuJoCo 里走的策略」：

1. 数据盘清出 ≥100GB  
2. 新建 `g1_train` conda + CUDA PyTorch  
3. 选 **Isaac Lab 或 MJX**（5090 优先这两条）  
4. 用 **12-DoF、47 维 obs、12 维 action** 对齐现有部署（减少改 `walk_g1.py`）  
5. PPO 训到「单环境 MuJoCo 评估不倒且能跟 vx」  
6. 导出 TorchScript → 替换/指定 `--policy`  
7. `walk_g1.py --no-view` 验收 → 再开 6008  

若愿意改部署代码，可重新定义 obs/action，但要把文档一里的对齐约束全部更新。

## 10. 小结

- **硬件：** 现有 5090 足够；关键是 **磁盘** 与 **CUDA 训练软件栈**。  
- **环境：** 数据盘独立 conda + CUDA PyTorch + Isaac Lab **或** MJX；不要用当前 CPU `mjviser` 环境训练。  
- **步骤：** 定规格 → Env/奖励 → PPO 训练 → 导出 JIT → 对齐 yaml/`walk_g1.py` → MuJoCo 验收 →（可选）真机。
